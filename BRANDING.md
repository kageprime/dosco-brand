# Dosco Agent Network — Frontend Reskin & Build Guide

This document explains how the **Dosco Agent Network** frontend is derived from the
upstream [kortix-ai/suna](https://github.com/kortix-ai/suna) codebase, how the
private "Dosco" branding is applied, and how to build, deploy, and keep it in
sync with upstream without losing your changes.

---

## 1. Context

You run the Kortix self-host stack via the `kortix` CLI. The stack is a Docker
Compose project named **`kortix-default`** rooted at:

```
/home/ubuntu/.config/kortix/self-host/default/
├── docker-compose.yml      # generated by the CLI; do NOT edit by hand
├── .env                    # image tags + runtime config (we edit FRONTEND_IMAGE here)
├── Caddyfile
└── volumes/
```

The running images (all `:0.13.5`) are pulled from Docker Hub:

| Component | Image | Rebuilt locally? |
|-----------|-------|------------------|
| Frontend  | `kortix/kortix-frontend` | **Yes** (this repo) |
| API       | `kortix/kortix-api`      | No — keeps `:0.13.5` |
| LLM Gateway | `kortix/kortix-gateway` | No — keeps `:0.13.5` |
| Supabase stack (db, auth, kong, storage, …) | supabase/* | No |

We only modify the **frontend**. The API and gateway stay on the upstream images
so the backend behaviour (agents, sandbox, billing, connectors) is unchanged.

## 2. Design: branding lives OUTSIDE the source tree

The hard part of a reskin is *keeping it across `git pull`*. If you edit the
Suna source directly, every upstream update conflicts.

**Solution:** the branding is an external **overlay** at
`/home/ubuntu/dosco-brand/`, applied to a *clean* Suna checkout right before each
build and then discarded. The Suna repo itself never stores your changes, so
`git reset --hard upstream/main` is always conflict-free.

```
/home/ubuntu/suna/            # upstream checkout (v0.13.5, branch local-dev)
        ↑ apply.sh stamps branding here (temporarily)
/home/ubuntu/dosco-brand/    # ← the reskin source of truth (this repo)
        config.sh            # branding variables
        transform-en.py      # rewrites translations/en.json
        apply.sh             # stamps assets + copy/text/link changes
        build-frontend.sh    # host build + docker buildx → kortix/kortix-frontend:local
        assets/              # Dosco logos / favicons
        BRANDING.md          # this file
```

Because the Suna working tree is restored to pristine before each apply, the
overlay is fully reproducible and re-applyable.

## 3. What the reskin changes

`apply.sh` performs, in order:

1. `git checkout -- apps/web` — guarantees a pristine base.
2. Copies Dosco logo/favicon assets over upstream's public filenames
   (`kortix-symbol.svg`, `kortix-logomark-white.svg`, `logomark-white.svg`,
   `kortix-brandmark-bg.svg`, `favicon.png`, `favicon-light.png`,
   `brand/chrome.svg`).
3. `transform-en.py` rewrites **every string value** in
   `apps/web/translations/en.json`:
   - `Kortix Computer` → `Dosco Agent`; `Kortix`/`Suna` → `Dosco`
   - removes "open source" / "self-host" / "MIT-licensed" phrasing
   - neutralizes GitHub / `kortix.com` external URLs (`#` or your canonical)
   - repoints `*@kortix.com` emails to `DOSCO_SUPPORT_EMAIL`
   - (JSON **keys** are preserved, so i18n references never break)
4. Patches `apps/web/src/lib/site-metadata.ts` (page title / SEO) and
   `apps/web/public/manifest.json`.
5. Removes external Kortix / GitHub / social links from the nav + footer
   (`site-config.ts`): X, LinkedIn, GitHub, Status, License links are deleted;
   the contact `mailto:` is repointed.
6. Global safety pass: neutralizes any remaining `kortix.com` / GitHub URLs in
   source, then rebrands any remaining whole-word `Kortix` in JSX/TS strings
   (whole-word only, so component identifiers like `KortixProjectScope` and
   package paths like `@kortix/sdk` are left intact).

> **Private-product decisions (set with you):** social/GitHub/"open source" links
> are *removed entirely*; support/contact emails are *repointed* to a Dosco
> address; the public landing page is *kept but rebranded*.

## 4. Build prerequisites (one-time)

- **Docker** (already present) + **docker buildx** (installed at
  `~/.docker/cli-plugins/docker-buildx`).
- **Node 22** and **pnpm 8.11.0** (via `corepack enable && corepack prepare pnpm@8.11.0 --activate`).
- The Suna repo cloned and `pnpm install` already run.

```sh
# verify
docker buildx version
node --version      # v22.x
pnpm --version      # 8.11.0
```

---

## 5. Build the local frontend image

```sh
cd /home/ubuntu/dosco-brand
bash apply.sh               # stamp Dosco branding onto /home/ubuntu/suna
bash build-frontend.sh      # → kortix/kortix-frontend:local
```

`build-frontend.sh`:
- sources the running `.env` (`/home/ubuntu/.config/kortix/self-host/default/.env`)
  to bake sane `NEXT_PUBLIC_*` fallbacks (runtime `KORTIX_PUBLIC_*` env overrides
  these inside the container, so this is only a fallback);
- runs `next build` with `NEXT_OUTPUT=standalone` in `apps/web`;
- runs the upstream "repair standalone Next package" step (pnpm symlink fix);
- `docker buildx build -f apps/web/Dockerfile -t kortix/kortix-frontend:local .`.

---

## 6. Deploy into the running stack

Two `.env` edits (already done) stop the self-host updater from overwriting your
image, and point the frontend at the local build:

```ini
FRONTEND_IMAGE=kortix/kortix-frontend:local
KORTIX_AUTO_UPDATE=false
KORTIX_IMAGE_PULL=never
```

Then stop the updater and recreate **only** the frontend (in the correct
`kortix-default` compose project — note the project name, it is *not* `default`):

```sh
cd /home/ubuntu/.config/kortix/self-host/default
docker compose -p kortix-default -f docker-compose.yml stop kortix-updater
docker compose -p kortix-default -f docker-compose.yml up -d --no-deps frontend
```

> ⚠️ Do **not** run a bare `docker compose up -d frontend` from this directory:
> compose would infer the project name `default` and try to spin up a *second*
> conflicting stack. Always pass `-p kortix-default`.

## 7. Update workflow (pull upstream, keep the reskin)

```sh
cd /home/ubuntu/suna
git fetch upstream
git reset --hard upstream/main        # or a release tag, e.g. v0.13.6

cd /home/ubuntu/dosco-brand
bash apply.sh                         # re-stamp Dosco branding
bash build-frontend.sh                # rebuild kortix/kortix-frontend:local

cd /home/ubuntu/.config/kortix/self-host/default
docker compose -p kortix-default -f docker-compose.yml up -d --no-deps frontend
```

Because branding is external and `apply.sh` restores a clean checkout first, the
`reset --hard` is always clean. Re-verify after each pull (see §9).

## 8. Customizing the brand

Edit `/home/ubuntu/dosco-brand/config.sh`:

```sh
DOSCO_SUPPORT_EMAIL="support@dosco.example.com"   # ← set to your real address
DOSCO_CANONICAL="https://dosco.example.com"       # ← set to your real domain
DOSCO_PRODUCT_NAME="Dosco Agent Network"
DOSCO_SHORT_NAME="Dosco"
```

Replace the placeholder logo/favicon files in `assets/` with your real brand
files **using the same filenames**, then re-run `apply.sh` + `build-frontend.sh`.

To change wording beyond the automatic phrase replacements, edit
`transform-en.py` (the `transform()` function) — e.g. add a `re.sub` rule.

## 9. Verification & rollback

**Verify after a build/deploy:**
- `docker ps | grep frontend` → `kortix/kortix-frontend:local`, healthy.
- Curl the container (port 3000) or the public URL; check for
  `Dosco Agent Network`, and that `open source` / `github` / `kortix.com` /
  `self-host` are absent from the served HTML.
- Confirm support emails and the title tag reflect Dosco.

**Rollback:**
```sh
# in the self-host dir .env:
FRONTEND_IMAGE=kortix/kortix-frontend:0.13.5
docker compose -p kortix-default -f docker-compose.yml up -d --no-deps frontend
```
The original `:0.13.5` image is retained as a fallback.

## 10. Known gotchas

- **Module-name trap:** the URL pass originally replaced the bare substring
  `kortix.com` everywhere, which corrupted the module `@/stores/kortix.computer-store`
  into a broken import. The pass now only rewrites full URLs
  (`https://kortix.com`, `https://github.com/kortix-ai`, …), never the bare
  `kortix.com` substring.
- **Compose project name:** the live stack is `kortix-default`, not `default`.
  Always use `-p kortix-default`.
- **Upstream restructuring:** if upstream renames a logo file or moves a nav
  link, the asset copy / link removal may silently miss. Always re-verify §9
  after a pull.
- **Disk:** a full build + image uses several GB. Monitor free space on `/`.
